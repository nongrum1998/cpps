# Dependency & Peer-Dependency Map

Generated by direct inspection of every `package.json`, the pnpm store layout, and
`pnpm-lock.yaml`. Use it to answer **"where do I edit to bump X?"** without grepping.

**Repo:** `pension-workspace` (private, pnpm 10.26.0, Node 22.22.3)

---

## 1. The one rule that governs everything

| Kind | Who picks the version | Per-app resolution | Safe across version skew |
|---|---|---|---|
| `dependencies` | package author | ✅ yes | ✅ |
| `peerDependencies` | **consumer** | ❌ **one global symlink** | ❌ |

**Why peers differ:** pnpm's default is `resolve-peers-from-workspace-root=true`. A
workspace package must physically typecheck against its peers, so pnpm installs them
into `packages/<pkg>/node_modules/` — resolved against the **root** context, not against
any consuming app. There is exactly one `packages/ui/node_modules/react` symlink on
disk, and it points at one version for everyone.

**The aggravating factor:** these packages ship **raw TypeScript** (`"main": "./src/index.ts"`,
no build step). When `apps/cpps` imports `@pension/ui`, Metro follows the symlink to the
*real* path (`/…/packages/ui/src/index.ts`) and resolves from there. The app's
`node_modules` is never in the resolution chain, so **the importer is invisible**.

Verified on disk:

```
apps/cpps/node_modules/react        -> .pnpm/react@19.2.3/…   ← per-app, correct
apps/eis/node_modules/react         -> .pnpm/react@19.1.0/…   ← per-app, correct
packages/ui/node_modules/react      -> .pnpm/react@19.2.3/…   ← SINGLE, global
```

> ⚠️ **The exact pins on peerDeps (`57.0.18`, not `^57.0.18`) are load-bearing.**
> They convert a silent runtime failure (`Invalid hook call`, wrong React context) into
> a loud install failure. Do not "clean up" them into carets while `apps/eis` is in the
> workspace and SDKs differ.

## 7. Operational hazards (independent of versions)

**1. `apps/eis` is silently a workspace member.** Root `pnpm-workspace.yaml` globs
`apps/*`, which matches it — but the lockfile has **no `apps/eis` importer**
(0 occurrences; importers are only `apps/cpps`, `apps/pension`, + 10 packages).
Consequence: the next root `pnpm install` rewrites `pnpm-lock.yaml` to add eis's entire
SDK 54 tree. Any `--frozen-lockfile` CI fails. There is no CI (`.github/` absent).

**2. `apps/eis/pnpm-workspace.yaml` is a broken leftover.**

```yaml
allowBuilds:
  unrs-resolver: set this to true or false   # scaffold placeholder, not a boolean
```

No `packages:` field, and a placeholder string where a boolean belongs. Running
`pnpm install` from inside `apps/eis` selects *this* file, not the root — two
independent install trees in one directory.

**3. `apps/eis/node_modules` does not exist.** It has `.expo/` state from its
standalone origin but has never been installed here.

**4. Tooling asymmetry silently skips eis.** Root `pnpm -r test` / `typecheck` no-op
for eis (no such scripts). eis's `lint` is `eslint --fix` — **mutating** — where the
others are check-only.

**5. No `packageManager` field anywhere.** Nothing pins the toolchain; corepack
cannot enforce it.

## 8. Update playbooks

### A. Bump a generic library (e.g. `zod`)
1. Edit every site in §5c.
2. `pnpm install` at root → lockfile updates.
3. `pnpm -r typecheck && pnpm -r test && pnpm -r lint`.
No package changes needed — no peer coupling.

### B. Bump Expo SDK (57 → 58) for the 57-group
1. Both 57 apps' `dependencies` + `devDependencies`.
2. All 8 packages' `peerDependencies` (and `packages/ui` devDeps).
3. `pnpm-workspace.yaml` → add new versions to `minimumReleaseAgeExclude`; move the
   24 old entries out.
4. `npx expo install --fix` in each app to realign transitive Expo packages.
5. `expo-doctor` in both apps; re-verify `metro.config.js` (`useWatchman`) and
   `babel.config.js` (worklets plugin).
6. `pnpm -r typecheck && pnpm -r test && pnpm -r lint`.
`apps/eis` is untouched throughout — it is already excluded by dependency absence,
but is *not* excluded from the lockfile (see §7.1).

### C. Share a package with eis
1. Confirm the package is in the "safe to share" list (§4). `@pension/api` and
   `@pension/types` qualify today.
2. Add the dep to `apps/eis/package.json` and run a root `pnpm install`.
3. If pnpm hard-fails on peers — **stop.** That is the exact-pin guard working.
   Do not widen the pin to a caret. Either decouple the package from Expo, or
   leave it unshared.

### D. Bring eis to SDK 57
This is an app-level migration, not a monorepo change. It makes `apps/eis` a consumer
of the packages above and resolves §4 entirely — but note the work: `expo-router`
6 → 57 is a breaking API change, and `react-native-worklets` 0.5.1 → 0.10.1 likely
requires reanimated config changes.
